# ADR-0014: 备份等序原则；恢复期禁止自动收敛（只读观察）

| 状态 | 日期 | 关联 |
|---|---|---|
| 已接受（v0.1 落地） | 决策 2026-09-17；收录 2026-09-29 | [state-model](../design/2026-09-17-state-model.md)（D-STM-6/7、§2.7）、`internal/statebackup`、[managed-databases](../design/2026-09-20-managed-databases.md)（恢复走备份重放） |

## 背景

备份/恢复与收敛引擎互动：恢复旧状态时若自动收敛仍开着，引擎会把「恢复出来的旧期望态」当成漂移拉回新态——静默回滚部署。

## 决策

1. **备份等序原则（D-STM-7）**：SQLite 允许比 raft（substrate 实况）**新**、绝不更**旧**——恢复出来的权威态不早于运行域实况的既有事实。
2. **固定恢复顺序**：先控制面备份（restic 仓库口令在首次控制面上传时惰性 provision），后库备份。
3. **恢复期禁止自动收敛，以只读观察模式替代**——这是 ADR-0004「检测与变更解耦」在恢复场景的强制形态。
4. **孤儿只登记、永不自动删（D-STM-6）**：对账发现的孤儿对象披露为事件/台账记录，删除必须人工。
5. **backup=控制面状态快照**（VACUUM INTO+回读校验入台账）；**restore 专属灾难恢复语义**（UL 词条：部署归位=replay，不得用 restore）。
6. VL 数据不进 state_backups（ADR-0006）；托管库备份=restic 快照+verify=verified 台账。

## 后果

- 「恢复中」是一个显式状态：UI/CLI 必须呈现只读观察模式，不许在恢复窗内发起部署/收敛。
- 备份面空白（backup_plan 未配置）是部署检查项而非事后发现。
