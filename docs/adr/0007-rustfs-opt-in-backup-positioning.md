# ADR-0007: RustFS=opt-in 管理组件；同节点备份=便捷层非灾备

| 状态 | 日期 | 关联 |
|---|---|---|
| 已接受（落地）；跨节点互备挂账（V3-3） | 决策 2026-09-20（V2-2，用户直裁）；收录 2026-09-29 | [object-storage](../design/2026-09-20-object-storage.md)（D-S3-2/9）、[v0.2 规划](../plan/2026-09-20-v0.2-plan.md)（V2-2） |

## 背景

S3 兼容对象存储自托管与否：RustFS 早期评估「仅 CI 代演」，1.0 GA（2026-04 之后）后触发 D4 重新裁决。

## 决策

1. **RustFS=opt-in 管理组件**（`s3.backend=rustfs`）：平台部署/卷钉住/凭证注入；**默认装不捆绑**；启用时计入预算复测。
2. **同节点备份是「便捷层非灾备」**（故障域问题）——Console/文档诚实标注；DR 语义仍指向外部端点或跨节点。
3. **对外口径**：可写「可选自托管 S3 兼容存储（RustFS）」，**不得写「内置 S3」**。
4. **zot 关键路径不垫 S3 后端**；**RustFS 不作 VL/VM 主存储**（引擎不支持）。
5. D-S3-9：内网+可选公网子域开关；D-S3-2：端点配置落库内运行期设置（platform_settings KV），不落 config.yaml。
6. **跨节点互备（node A↔B 零云依赖真 DR）挂账**（V3-3）：届时对比 restic-SFTP（零新组件）vs 对端 RustFS 再裁决。

## 后果

- 备份目标语义分层：外部端点=DR / 本机 RustFS=便捷层——UI 与文档必须分层表达。
- RustFS 上线后有部署序约束：库备份前必须先跑一次控制面备份（restic 仓库口令首次控制面上传时惰性 provision）。
